01

Outcome and boundaries

A language is complete only when the surrounding states—errors, accessibility text, auth, progress, and realtime feedback—are complete too.

One product, two complete presentations

Every app-owned screen and Learning Guide is available in English and neutral Latin American Spanish. Spanish uses a direct “tú” voice. “Upsolving” remains the canonical label in both languages.

Translate

  • Navigation, forms, filters, tables, statuses and actions
  • Auth and in-app Clerk components
  • Toasts, loading, empty and failure states
  • ARIA labels, alt text and guide content
  • Number, date, time, percent and visible sort behavior

Keep verbatim

  • Judge, contest and problem names from providers
  • Handles, tags and technical identifiers
  • C++ code, values and executable expressions
  • Raw Playground payloads and diagnostic output
  • Routes, analytics events and machine-facing enums

09

Risks and research

Header overflow

Spanish labels are longer, so desktop utilities and navigation get separate rows. Below lg, navigation moves into the menu; below sm, Sync is icon-only and language becomes a full-width menu row.

Silent English leakage

Use typed keys, namespace parity tests and i18next-cli lint. Production fallback is safety, not the completeness check.

Server prose as contract

Convert normal UI paths to error codes and parameters. Preserve raw detail only for logs and Playground diagnostics.

Clerk localization maturity

Use esMX behind an adapter, add project overrides, and test in-app Clerk surfaces. The hosted Account Portal remains external.

In-progress Resources work

Treat the current dirty working tree as the baseline. Refactor the existing guide and roadmap without discarding or recreating those changes.
