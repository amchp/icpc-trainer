Brute Force:
generate, check, backtrack.

A problem-first class that teaches learners to read the bounds, estimate the search space, and reach for the simplest exhaustive solution that fits.

Source and direction Based on Fuerza Bruta.pdf. Preserve its progression from direct enumeration to permutations, subset generation, and backtracking, while rebuilding the material in ICPC Trainer’s app-native visual language.

01

Decisions already locked

These are product decisions, not open questions for the implementer.

Scope

One new Learning Topic and Guide

Add the third roadmap node after Programming Fundamentals. Access remains open; the prerequisite is recommended, never enforced.

Vocabulary

Say “generate subsets”

Learner-facing copy uses permutations, subset generation, and backtracking. Do not use “combinatorics” as the section label.

Code depth

Fragments, not complete programs

Show signatures, core loops, recursive calls, traces, and complexity. Leave input parsing and the final accepted program to the learner.

Presentation

App-native visuals

Recreate useful ideas as state traces, search trees, grids, and counters. Do not ship screenshots or memes extracted from the source PDF.

Method order

Recursive first, iterative second

Establish the decision tree, then derive next_permutation and bitmask enumeration as compact contest implementations.

Localization

English and Spanish at launch

Add matching catalogs and localized code fragments. Preserve the existing bilingual Resources journey and catalog-shape checks.

02

Lesson arc

The curriculum moves from counting candidates to pruning them. Each worked problem starts with a brief attempt before the technique is named.

00 Read the bounds Count candidates and total work before choosing an algorithm.
01 Simulate Repeat a known process and check whether the target appears.
02 Permute Generate every ordering recursively and iteratively.
03 Choose Generate every binary choice with recursion and bitmasks.
04 Backtrack Reject invalid partial candidates and undo failed choices.
00

Bounds before algorithms

Introduce the candidate-counting habit with an interactive meter. Learners vary n, test cases, and per-candidate work, then compare n!, 2^n, and 3^n.

BigInt counts heuristic bands n = 1…20 full input budget
Success signal The learner can explain why multiplying by test cases and work per candidate can change an apparently small bound.
01

Alice’s Adventures in “Chess”

Begin with a paraphrased prompt, sample path, target, and constraints. Reveal direct simulation: update (x, y), repeat the known movement sequence, and check the target after every move.

quick pause path trace finite guard
Code shown The movement update loop and target check only. Explain the bound instead of using an unexplained magic number.
02

Kitchen Plates

Generate an ordering of ABCDE, then check all five comparisons. Trace recursive placement with used[] first; follow it with sorted input plus next_permutation.

5! candidates call stack next_permutation
Comparison Recursion exposes the decision tree; the standard-library form is compact when every complete ordering must be checked.
03

Sakurako’s Exam

Treat each sign as a binary choice. Trace recursive + / - branches, then enumerate the same choices with masks from 0 through (1 << n) - 1.

choose + / − 2^n candidates bitmask mapping
Complexity shown Use O(t · n · 2^n), not just O(2^n). Do not present the fragment as an acceptance guarantee across every worst-case input.
04

Sudoku backtracking capstone

Select an empty cell, try a digit, reject invalid candidates, recurse, and reset the cell when a branch fails. Use a small deterministic trace, not a full animated solve.

try validate recurse undo
Visual shown Synchronized code line, call stack, and accessible Sudoku grid with fixed, active, accepted, and rejected cell states.

Closing transfer practice

These remain at the end of the guide. Each gets two or three progressive hints and an expected complexity, but no full in-app solution.

You’re Given a String…

Lead toward two start positions and a candidate length. Count the cost of creating and comparing substrings, not only the visible loops.

Chocolate Packing

Treat the small box orientation as one of 3! dimension permutations and maximize the product of three integer quotients.

Barbells

Explain the three states for each plate—left, right, unused—so m ≤ 14 becomes a feasible 3^m search. Keep balanced assignments, combine them with each barbell, deduplicate, and sort.

03

Problem-first experience

The pause is short and learner-controlled. It should create productive friction without locking the rest of the guide.

Problem Prompt, sample, constraints
→
Quick pause Form an idea and sketch the code
→
Reveal tool Only when progress stalls
→
Trace + fragments Understand, then implement
Attempt copy: “If you already have an idea, pause and think through how you would code it. If you are sitting here with no way to make progress, show the tool and use it to unlock the problem.”
Reusable UI

ProblemFirstChallenge

Renders the paraphrased problem, constraints, sample, original Judge link, attempt prompt, and an accessible aria-expanded reveal. On reveal, move focus to the technique heading.

Interactive concept

SearchSpaceMeter

Uses exact BigInt counts, includes all test cases and per-candidate work, and labels feasibility as a cautious heuristic rather than a runtime promise.

Practice support

ProgressiveHints

Reveals hints in order, with expected complexity last. It never includes a complete solution and never writes reveal state to the backend.

Trace extension

Typed grid visual

Extend the existing trace visual union so Sudoku can synchronize code, narration, call stack, and cell state through the established trace player.

08

Risks and safeguards

Complexity

A small per-case bound can still mislead

Always include test cases and per-candidate work. Sakurako explicitly uses O(t · n · 2^n) and avoids claiming automatic acceptance.

Length

The guide could become another fundamentals monolith

Keep exactly four worked cycles, use fragments rather than programs, and move String, Chocolate Packing, and Barbells into one closing practice bank.

Trace size

Recursive trees can explode in the browser

Trace only tiny fixed inputs and cap recorded frames. The Sudoku trace demonstrates one failure and undo path rather than solving a full board.

Source use

Slide screenshots reduce clarity and complicate reuse

Paraphrase the prompts, link to the original Judge statements, and create native diagrams. Do not copy full statements or PDF images into the app.

Shared controls

New guide UI could depend on the wrong namespace

Move generic control labels to a shared learning namespace and verify that the existing Fundamentals guide is visually unchanged.

Mobile

Code, grids, and controls can widen the page

Constrain overflow to local panels, stack code and state on narrow screens, and include a 320px document-width assertion in the Resources e2e journey.

09

Definition of done

  • A third Brute Force guide follows Programming Fundamentals.
  • The guide is complete in English and Spanish.
  • Every worked topic begins with a quick attempt.
  • Permutations use recursive and iterative generation.
  • Subset generation uses recursive and bitmask forms.
  • Sudoku closes the guide with backtracking.
  • No worked example exposes a complete copy-paste program.
  • Three practice problems use progressive hints.
  • Barbells receives a conceptual three-state explanation.
  • Only guide-level progress persists.
  • All controls work with keyboard and reduced motion.
  • Unit, integration, e2e, typecheck, and build checks pass.
